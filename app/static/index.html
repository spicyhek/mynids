About(1 panel)

How it works

A Zeek sensor on my homelab cluster turns network traffic into flows, and a machine learning model sorts each flow into a class. Flows whose detection quality hasn't been measured here are counted as unvalidated.

Benign
Traffic the model predicts is normal.
Botnet
Traffic the model predicts resembles activity from compromised machines. Since November 10, 2026 new botnet predictions are counted as unvalidated: they have only matched benign traffic here.
Brute force
Traffic the model predicts resembles repeated login attempts against SSH, FTP or web logins.
DoS / DDoS
Traffic the model predicts resembles denial-of-service activity.
Other attack
Model predictions for a combined class covering infiltration, port scans, XSS and SQL injection. Flows labeled by the earlier model also count brute force here.
Unvalidated
Flows with unverified detection quality: botnet predictions, flows the model could not judge (such as the first minute after a sensor restart), and ICMPv6 that is not routine. Since November 2026, routine IPv6 housekeeping (neighbor discovery, multicast listener reports, pings and error messages at normal volume) is counted as benign by a rule; router advertisements, redirects and unusually heavy ICMPv6 stay unvalidated. Included in flow totals, but counted separately from benign and suspected attacks.
Web probes
HTTP requests for paths only scanners ask for, such as .env, .git or other dotfiles, WordPress or PHP files. Detected from request paths, not by the model, and counted separately from flows.
Web scans
One client's burst of web probes and other failed requests, grouped into a single event: at least 10 requests for 5 different paths with no pause over a minute. The flow model rarely flags these, because the reverse proxy hides each scanner behind its own address. Served counts probe paths that were answered with content instead of an error.
